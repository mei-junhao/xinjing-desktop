# 5.0.0 开发边界契约 v1

## 目标

把此前版本的临床闭环和 5.0 商业底座放在同一份可验收边界中。该文件是开发契约，不是发布授权。

## 合同对象

| 域 | 允许新增 | 明确禁止 |
|---|---|---|
| 临床数据 | 复用既有对象、引用、快照和 durable API | 为商业服务复制临床正文、逐字稿、报告、督导或资料库正文 |
| 账户/设备 | 匿名账户、设备摘要、授权绑定、撤销和换机状态 | 真实身份、设备私钥、临床路径或密钥进入日志/群消息 |
| 订单/额度 | 合成订单、状态机、对账结果、算力余额和请求包使用记录 | 真实支付、真实订单、真实凭据或未经授权的外发 |
| 权益 | Free/Pro/Flagship/Trial 统一 feature registry | 页面私建档位判断、Trial 升档、未知 key 放行 |
| 督导包 | recipient grant、包哈希、版本、撤销和错误状态；单 grant 单活设备；换机重封装并撤销旧设备 | 把 `.xjsup` 文件存在当成可运行授权，执行任意代码，或让 author 私钥进入仓库/构建/客户端 |
| IPC | 类型化请求、最小响应、超时、取消、去重和错误码 | renderer 读取签发私钥、代理密钥、完整输入/输出或任意 IPC |
| UI | 沿 activation/settings/billing/supervision 现有身份渐进融合 | 新增孤立一级入口、改写生产默认皮肤或删路由 |
| 发布 | 只保留本地证据和未签名 internal candidate 语义 | pack、sign、upload、push、publish、远程 manifest 更新 |

## 统一状态机

商业状态必须能表达：`created -> pending -> active -> expired -> revoked`，并明确 `refunded`、`transfer-pending`、`transfer-completed`、`offline-grace`、`blocked` 和 `unknown`。未知、签名失败、时钟异常、撤销列表回滚和跨设备不匹配一律 fail-closed，但保留 Free 手动数据访问。

## 证据要求

- 合成 fixture 与真实入口执行证明，不接受只扫描源码字符串。
- 正向、拒绝、撤销、过期、重复、乱序、断网、超时、取消、恢复和跨设备矩阵。
- 至少一次删除 `await`、替换 durable API、吞掉 `{ok:false}`、绕过 handler、替换 entitlement registry 的反向变异；变异存活即 FAIL。
- 报告末行严格为 `DELIVERY_REPORT: <absolute-path>`。

## 版本门禁

5.0.0 开发完成不等于 released。前版本不打包政策持续有效；候选 SHA、内部评分、无上下文独立评审、P0/P1、安装/升级/回滚和用户发布授权均独立记录。
