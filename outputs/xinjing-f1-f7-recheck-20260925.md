## 二、F4 新发现的缺陷与修复

先在 `scripts/f4-durable-txn.test.cjs` 增加四个红项：同 ID 督导的同步/异步更新覆盖他窗口不同字段，以及他窗口删除后由旧 cache 复活。原代码四项均失败。随后 `app/js/store.js` 的 `updateSupervision` 在原位更新前克隆基线，`updateSupervisionDurable` 保留基线；两者共用 `persistSupervisionPatch`，在 IndexedDB 单事务内按字段差量合并，目标已删除即零写入；降级路径也使用同一字段 patch，并加入同步队列维持创建→更新顺序。复测 durable 48/48、degraded 47/47。

这是 fake IDB/VM 强约束验证，不冒充真实 Chromium 双窗口证明。历史双窗口 10×10 的证据对应旧版 `store.js` MD5，不能挪用于最新修复代码。隔离真实 Electron 双窗口尝试受当前环境 renderer/GPU 崩溃阻断；**当前哈希的真实双窗口验收记为 BLOCKED/UNTESTED**。独立复审另指出同步 `updateSupervision` 先修改内存并返回，若持久化失败目前仅警告、未回滚；提交完成后 cache 数组替换还可能使已返回的活引用脱离 cache，同字段并发修改亦没有版本冲突检测。这些风险没有通过当前专项测试消除，后续必须设计明确的 API 语义和失败/冲突回归，不得用异字段通过推断同字段安全。
